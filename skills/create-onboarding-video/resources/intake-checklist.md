# Intake Checklist

Use this checklist before storyboarding or writing Remotion code. Ask the user concise questions in normal chat when required inputs are missing.

## Required

- **Screenshots:** 2-4 stills per onboarding screen or beat.
  - Resting state.
  - Interaction state, such as pressed, focused, dragged, loading, or sheet partially open.
  - Result state.
  - Any important variant, such as empty/filled, success/error, light/dark, or permission state.
- **Feature intent:** one or two sentences explaining what this feature does for the user and why the moment matters.
- **Flow order:** the sequence of screens or beats to show.
- **Target output:** aspect ratio, duration limit, and whether this is an onboarding clip, App Store preview, social cutdown, or internal demo.

## Strongly Preferred

- Brand or accent color, font, and any "do not change" UI constraints.
- Desired caption copy, CTA/end card copy, or confirmation that captions should be minimal.
- Platform target, such as iPhone portrait 1080x1920 or an App Store preview size.
- Any reference video whose pacing or style the user likes.
- Delivery needs: MP4, transparent intermediary, poster frame, portrait/landscape variants, or source handoff.

## Intake Prompts

Use only the questions that close real gaps:

- "Please send 2-4 screenshots for each screen: resting, interaction, and result states."
- "What single feature should this video prove?"
- "What order should these screens appear in?"
- "Should this target 1080x1920 portrait, App Store preview specs, or another format?"
- "Any brand colors, fonts, captions, or end-card text I should preserve?"

## Ready To Proceed

Proceed only when screenshots and feature intent are available for every planned screen. If the user supplies fewer stills, explain which interaction state is missing and what tradeoff that creates.
